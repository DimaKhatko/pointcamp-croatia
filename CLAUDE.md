## Standard v1 rules (S1–S5, concise)
- **S1 Lead submission.** Target end-state: `src/lib/submitLead.ts` posting JSON to the Make webhook `https://hook.eu1.make.com/29wyg57rzqxtajir3fw537ce1vrs2ev2`. Payload keys exactly: `landing, name, phone, email, participant, page_url, utm_source, utm_medium, utm_campaign, utm_content, utm_term, submitted_at, test`. Retry once after 1500 ms on network/non-2xx failure. Push `{ event: "lead_submit" }` to `window.dataLayer` **only after a confirmed 2xx** (SSR-guarded). Form via `FormData`, names `name/phone/email/participant`. No honeypot field: every valid submit goes to `submitLead`. No `VITE_*` tokens and no browser calls to third-party APIs (e.g. `api.telegram.org`) in client code.
- **S2 Analytics.** GTM container `GTM-PGJNFD95` is the only tracking loader. `window.dataLayer` is declared by a one-line inline script in `<head>`; gtm.js itself is injected by `GTM_LOADER` (inline, start of `<body>`, `src/routes/__root.tsx`) 3 s after `load` or on the first pointerdown/scroll/keydown/touchstart, whichever comes first, pushing the standard `gtm.js` event. Keep the `<noscript>` iframe. No direct gtag.js, no fbq/fbevents, no second GTM. `window.dataLayer` typed once. Allowed custom events: `lead_submit`, `video_play`.
- **S3 Meta & crawl.** `<html lang="uk">`; title; meta description; absolute canonical; `og:title/description/image` (absolute, image 1200×630), `og:url`, `og:type`, `og:locale=uk_UA`, `og:site_name="Point Camp"`; `twitter:card=summary_large_image`; `theme-color`; favicon. `robots.txt` with explicit `Allow: /` for Googlebot, Bingbot, the AI search/assistant bots (OAI-SearchBot, ChatGPT-User, PerplexityBot, Perplexity-User, Claude-SearchBot, Claude-User), the training bots (GPTBot, ClaudeBot, Google-Extended), Twitterbot, facebookexternalhit and `*`, plus a `Sitemap:` line. `sitemap.xml` with `<lastmod>` (bump it on every content deploy). **AI-search readiness (GEO):** everything a crawler needs must be in the prerendered HTML as text, because AI crawlers do not run JS and do not click: FAQ answers are always mounted (`FAQ.tsx`, `forceMount` + CSS collapse, closed answers `inert`), and the single JSON-LD `@graph` in `src/routes/index.tsx` (`structuredData()`: Organization with the shared `@id` `https://pointcamp.com.ua/#organization`, WebPage, Event with the public Offer, FAQPage) must match the visible copy. Check after a build: `grep -ac "<phrase from an FAQ answer>" dist/client/index.html` returns 1 or more. `public/og-image-v2.jpg` (1200×630) is generated by `scripts/generate-og-image.mjs` (dev-only, not part of the build): photo `safety-team.webp` + purple band with logo and tagline.
- **Bing Webmaster verification (permanent).** `<meta name="msvalidate.01" content="BF4250F50D78E77F8D1A4C8F71BA2B54">` sits next to the description meta in `src/routes/index.tsx`; never remove it (that unverifies the site in Bing Webmaster Tools).
- **S4 Build & hosting.** `vite.config` uses `nitro: false`, `spa: { enabled: false }`, `prerender: { enabled: true, crawlLinks: false }`, `pages: [{ path: "/" }]`: the page text must be in the HTML before any JS runs (LCP, crawlers, AI search). `firebase.json`: `public = dist/client`; **no catch-all rewrite** (the `/` HTML must only hydrate on `/`; unknown paths get the static `public/404.html` with status 404). Cache-Control: `/assets/**` `public, max-age=31536000, immutable`; `/hero/**`, `/hero-bg/**` and `/video/**` `public, max-age=604800` (unhashed files: rename a file when its content changes); root icons/og `max-age=86400`; `/` and `/index.html` `no-cache, no-store, must-revalidate`. `.firebaserc` target `croatia` → site `pointcamp-croatia-2026`. `.gitignore` contains `.firebase/`, `dist`, `*.report.html`.
- **S5 Subfolder readiness (prep only; "/" must not change).** No hardcoded root-absolute asset URLs in TS/TSX/CSS/HTML — use imports or `import.meta.env.BASE_URL`. Absolute `https` URLs in meta tags are fine. Router would take a base path via `createRouter({ basepath })` + Vite `base`; do not set either yet.

## Conventions
- Work on `main`. No feature branches, no Firebase preview channels.
- Prompts and code comments in English.
- Never write shell commands with `#` comments.
- Assets must be committed to be visible (nothing is fetched at deploy time).
- Measure layout shift and load timing on the static output (`bunx serve dist/client -p 5000`), not `vite preview`: Firebase hosts exactly these prerendered files, so font/CLS/LCP timing matches production.
- The display font is preloaded in `src/routes/__root.tsx` (same hashed file the CSS `@font-face` uses). Keep the two in sync: it removes the font-swap layout shift, which was 0.2–0.29 at 768–1023px before. The shipped file is the subset `src/assets/fonts/KyivTypeSans-Sub.woff2` (wght 400–800, Latin incl. Extended-A for š/č/ž, Cyrillic, used punctuation, 41 KiB) built from `KyivTypeSans-VarGX.woff2` by `scripts/subset-font.py` (`pip install fonttools brotli`); re-run it if the page starts using characters or weights outside that set.
- **Code splitting.** Sections below the first screen with heavier code (Moments/video, ForWhom, PineBeachResort, Reviews, DatesPricing, FAQ, ApplicationForm) and the sonner Toaster are `React.lazy` chunks; they are still prerendered into the HTML and hydrate when their chunk arrives. `VideoCard` mounts the `<video>` only near the viewport.
- **Pricing.** The price ladder (dates in Europe/Kyiv, prices) lives only in `src/lib/pricing.ts`. Everything that shows a price reads from it on the client after mount (`usePriceState`, skeleton until then): the price block, the Hero price chip and the FAQ answer (the application form shows no price). The "Знижки" block is hidden while `DISCOUNTS` in `data.ts` is empty (currently empty); payment terms (advance 500 €, −50 € for full payment) live only in the FAQ "Який порядок оплати?", not in the price card. Until 2026-10-31 the site is for returning participants only: the chip reads "1 300 € · для своїх", and the presale price must **never** be published to crawlers. The JSON-LD `offers` in `src/routes/index.tsx` is computed at build time by `getPublicOffer`: until 1 Nov 2026 it is 1450 € with `validFrom 2026-11-01`, afterwards the current tier. The site must therefore be rebuilt and redeployed on every switch date (**1 Nov 2026, 1 Jan 2027, 1 Apr 2027**) or crawlers will read a stale price. Tier names never appear in the UI. **Skeletons are sized from the build-day tier:** `scripts/write-build-date.mjs` (run by `bun run build` / `build:dev`) writes `src/lib/buildDate.generated.ts` (`BUILD_DATE`, Kyiv calendar day; override with `BUILD_DATE=YYYY-MM-DD` for tests). Before mount `usePriceState` returns that tier and the price block and Hero chip render it as transparent text on a pulsing background, so nothing shifts when the site is rebuilt on the switch date; a missed rebuild only causes a one-time shift. Always build via `bun run build` (plain `vite build` skips the date script) and commit the regenerated file.
- Lockfile: `bun.lock` is the only lockfile (`package-lock.json` is not used and stays gitignored).
